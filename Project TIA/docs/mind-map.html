  root((Key Concepts\nto Learn))
    **Multi-Tenancy**
      Every table has tenant_id
      Row-Level Security enforced
      tia_app role has no BYPASSRLS
      set_config per transaction
      Tenant registry via TenantAdmin
    **Evidence Statuses**
      source_confirmed
        Direct code evidence
      contract_confirmed
        Pact-like contract
      runtime_observed
        Future: runtime traces
      corroborated
        Multiple signals agree
      inferred
        Pattern-based guess
      stale
        Evidence is outdated
    **Resolution Strategies**
      R1: Generated/shared client
        Package matches service map
      R2: Fully resolved HTTP call
        Host + path both known
      R3: Declared contract
        Pact JSON files
      R4: Service map
        tia-services.yaml
      R5: Unique path match
        Only one endpoint with that path
    **Severity Rules**
      Critical: breaking + critical service
      High: breaking + confirmed
      Medium: non-breaking + confirmed
      Low: same-repo change
      Cap at Medium for inferred/stale
    **Incremental Extraction**
      Git blob SHA as cache key
      Per-file facts cached
      Assembly combines all files
      Incremental equals full rescan
      Force flag for full rescan
    **Graph Versioning**
      Content-addressed: SHA-256
      Same inputs = same version ID
      Immutable once persisted
      Head pointer for landscape
      Old versions stay readable
    **Audit Chain**
      Append-only log
      Hash-chained per tenant
      Optional HMAC key
      seq + prev_hash linkage
      Verifiable integrity
    **Job Queue Properties**
      Idempotent: same key = same job
      Group superseding: newest wins
      Fair: round-robin across tenants
      Reliable: lease-based at-least-once
      Exponential backoff retry

📖 Module Quick Reference

Hover on any card for a highlight. Each card explains what a module does and its key responsibilities.

server.py ENTRY

Boots the ASGI server. Reads environment variables, creates the Database, Store, and RepoService, then hands them to the FastAPI app.
  • Uvicorn binds to TIA_HOST:TIA_PORT
  • Reads 13+ environment variables
  • Single-tenant until SSO (PL-001)

api.py ENTRY

FastAPI application with all REST endpoints. The entire API surface is defined here: repositories, uploads, analyses, graph, webhooks, audit, and jobs.
  • create_app() is the main factory function
  • Endpoints return dicts (auto-serialized as JSON)
  • X-TIA-Readable-Repos header for audience filtering
  • Async upload handlers for streaming

cli.py ENTRY

Command-line interface for running analyses without a server. Supports JSON and Markdown output, and can post PR comments directly.
  • tia analyze --target X --base B --head H
  • Optional DB persistence via --db-url
  • Directly calls impact.analyze()

worker.py ENTRY

Background job processor. Polls the PostgreSQL job queue, claims work, runs handlers, retries on failure with exponential backoff.
  • Lease-based: heartbeat keeps the job alive
  • PermanentError = no retry
  • Two job kinds: impact_analysis, github_pull_request

analysis_service.py SERVICE

Orchestrator between the API and the impact engine. Resolves symbolic refs to exact commits, executes analyses, manages the landscape graph, and handles PR events.
  • resolve(): branch/PR → commit SHAs
  • execute(): runs the full analysis pipeline
  • refresh_landscape(): re-extracts all repos
  • make_handlers(): creates worker job handlers

repos.py SERVICE

Repository lifecycle: register, clone, fetch, sync, and remove. Supports GitHub, Azure DevOps, generic git URLs, local paths, and uploaded code.
  • Tokens via env vars (never on CLI or disk)
  • SSRF protection via allowed_hosts
  • Auto-discovery of org repos
  • commit_upload(): turns uploads into git repos

impact.py SERVICE

The change-impact engine. Takes a base/head diff, seeds the graph with changed nodes, does BFS traversal to find affected components, and generates severity-scored findings.
  • BFS with configurable max depth (default 8)
  • Time-budgeted (60s default)
  • Produces an evidence snapshot for reproducibility
  • Contract diff for breaking changes

graph.py GRAPH

In-memory typed dependency graph. Nodes are code entities (endpoints, functions, schemas, tests); edges encode relationships (HANDLES, CALLS, CONSUMES_API, TESTS, etc.).
  • impacted_by(nid): reverse traversal index
  • Edge types: HANDLES, CALLS, CONSUMES_API, USES_SCHEMA, ISSUES, TESTS, EXPOSES
  • Built from RepoExtract + consumer resolution

graphview.py GRAPH

Read-only views of the dependency graph at three levels (service, endpoint, function). Supports search, focus+depth, and impact overlays for analyses.
  • Service: one node per microservice
  • Endpoint: services + endpoints + schemas
  • Function: everything extracted
  • Impact overlay: highlight affected nodes

resolve.py GRAPH

Consumer resolution: the only place cross-repository edges are created. Five enumerated strategies (R1–R5) ensure relationships are evidence-backed.
  • R1: Generated/shared client (package match)
  • R2: Fully resolved HTTP call (host+path)
  • R3: Declared contract (pact-like JSON)
  • R5: Unique path match (inferred)

relationships.py GRAPH

Tracks cross-repo relationships over time. Detects when evidence goes stale (scan failure, parse failure, evidence removed) and reconciles against the latest graph.
  • States: current or stale
  • Stale reasons: scan_failed, parse_failed, evidence_removed
  • Reconciliation on every landscape refresh

extraction.py EXTRACT

Incremental extraction orchestrator. Uses git blob IDs as cache keys so only changed files are re-parsed. Assembles per-file facts into a RepoExtract.
  • Cache key: repo|service|strip|version|blob|path
  • force=True for full rescan
  • Guarantees: incremental result == full rescan

extract_python.py EXTRACT

Python source adapter using stdlib ast. Extracts endpoints (FastAPI/Flask), schemas (Pydantic), outbound HTTP calls, functions, tests, and service configuration.
  • Decorators: @app.get, @router.post, etc.
  • Clients: requests, httpx session calls
  • Tests: pytest, unittest with HTTP call matching
  • Service map: tia-services.yaml

extract_java.py EXTRACT

Java source adapter using tree-sitter. Full Spring Boot/Web support: controllers, DTOs, OpenFeign clients, RestTemplate, WebClient, JPA entities, JUnit tests.
  • Annotations: @RestController, @RequestMapping
  • Feign: @FeignClient interface resolution
  • Schema reachability: only endpoint-linked DTOs
  • Modern Java: records, var, text blocks

extract_data.py EXTRACT

Data-layer adapter for schema migrations. Parses Flyway, Liquibase, Alembic, and Django migration files. Also resolves ORM entity mappings at assembly time.
  • SQL: CREATE/ALTER/DROP TABLE parsing
  • Liquibase: XML/YAML/JSON changelogs
  • Alembic: op.create_table, op.add_column
  • Django: CreateModel, AddField, etc.

extract_orm.py EXTRACT

Python ORM adapter for SQLAlchemy, SQLModel, and Django models. Maps model classes to database tables and tracks data access patterns in functions.
  • Declarative + Mapped/mapped_column styles
  • Django model field detection
  • Read vs write operation classification
  • Raw SQL usage detection & reporting

db.py STORAGE

PostgreSQL access layer. Connection pool with tenant-bound transactions. Every tx sets tia.tenant_id for row-level security. Separate admin path for migrations.
  • Database: runtime (tia_app role)
  • TenantAdmin: admin-only tenant registry
  • migrate(): applies SQL from migrations/

store.py STORAGE

Tenant-scoped persistence facade. Wraps all database operations: evidence cache, file extract cache, graph versions, repo registry, analysis results, and HMAC-chained audit log.
  • All methods run inside db.tx(tenant_id)
  • Audit chain: prev_hash | seq | ts | event
  • Optional HMAC key (external to DB)

jobs.py STORAGE

PostgreSQL-backed job queue. Producer side (enqueue/get/cancel) is tenant-bound; consumer side (claim/heartbeat/succeed/fail) uses the worker role across tenants.
  • Idempotent: same (tenant, key) = one job
  • Group superseding: newest wins in a group
  • Fair scheduling: fewest-running tenant first
  • Lease-based with reap_expired()

models.py MODEL

Canonical data structures shared across the codebase. Dataclasses for every code entity: Endpoint, Schema, CallSite, Function, TestCase, Entity, DataAccess, Migration, Edge, RepoExtract.
  • Evidence statuses: source_confirmed → stale
  • Analysis statuses: running → complete/failed
  • Path normalization: normalize_path()

webhooks.py INFRA

SCM webhook receiving. Verifies GitHub HMAC signatures, parses pull_request events, matches incoming repos to registered ones, and provides ScmConfig.
  • Constant-time HMAC comparison
  • Actions: opened, reopened, synchronize, ready_for_review
  • URL-based repo matching (case-insensitive)

upload.py INFRA

Code upload handling. Accepts ZIP archives or folder batches, validates paths (no traversal, no device names), enforces size limits, and commits to a TIA-owned bare git repo.
  • Path sanitization: no .., absolute, device names
  • 2 GiB / 200k file limits (configurable)
  • Session-based: start → upload chunks → commit
  • Deduplication: identical content = same commit

gitutil.py INFRA

Read-only git access. Wraps git CLI commands for tree listing, blob reading, diff, and rev-parse. Never executes repository code. Used by extractors and impact engine.
  • list_tree(): path → blob SHA mapping
  • read_blobs(): batch content read via cat-file
  • changed_files(): name-status diff

github.py INFRA

GitHub PR comment publisher. Finds existing TIA comments by a hidden marker, updates in place or creates new. Uses urllib (no requests dependency).
  • Marker: <!-- tia-analysis -->
  • Upsert: create or update one comment per PR
  • Paginates through existing comments
